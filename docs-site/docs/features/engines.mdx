The fastest-moving part of the agent stack is the inner loop: the model-driven
process that decides what to do next. UseAgent deliberately does not compete
with it. **Engines are rented**: OpenCode, Pi, Codex, and Claude run behind
provider drivers or compatibility adapters, while UseAgent owns commands,
policy, durable records, knowledge, and rendering. Direct chat uses the same run
model without a workstation.

## One boundary, several execution paths

An adapter (`backend/src/engines/`) translates between an engine's native
protocol and UseAgent's thread, command, and event contracts. Above the adapter,
common behavior uses shared contracts:

- The timeline renders [canonical events](/features/agent-contract), never a
  provider's private schema.
- Most surfaces are gated on the session's **negotiated capability map**. A few
  provider-aware interaction paths remain where native ownership matters.
- Provenance stays honest: every event retains the engine's native ids in its
  identity, and the raw native frames are kept as a bounded sidecar for
  debugging.

The base engine set ships enabled, and the `ENABLED_ENGINES` environment list
can only **add** engines on top of it, never disable the base
(`backend/src/env.ts`). The composer's engine picker reflects exactly the
enabled set.

Sandbox-backed engine processes are resident per thread and reused across
turns. OpenCode uses `opencode serve`, Pi uses its RPC bridge, the runtime path
uses its orchestration service, and ACP keeps a resident relay. Persisted session
metadata includes protocol identity and a generation counter so stale session
ids are not replayed against a newer process generation. Subscription-backed
sessions also bind a credential epoch, which must still match before out-of-turn
resume, cancel, or recovery.

Each driver declares supported lifecycle operations and steer inputs beside its
model policy. The validator requires the `resume`, `stop`, `reconcile`, and
`modelSelection` capability flags to match those declarations. Compatibility
adapters can return typed unsupported results without advertising the operation.

## Readiness is credential-mode aware

A release proves the path that matches how an engine actually authenticates:
a subscription-only Codex release proves the connected account and the native
turn path, while an API-key engine proves its mapped gateway provider
(`backend/src/runs/engine-readiness.ts`). Model choice follows the same
honesty: the per-turn model picker appears only for engines whose capability
map advertises `modelSelection`.

## Why renting wins

Engine quality improves monthly, and adapter code is small compared to a
harness. Because every engine lands in the same product contracts, adopting
another engine is mainly a driver, translation, capability, and readiness task.
A thread stays on the engine it started with (a reply with a
different engine is rejected explicitly rather than silently rebound), while
the model can change turn to turn where the engine allows it. The full
mechanics live in [Engines and adapters](/concepts/engines-and-adapters).
