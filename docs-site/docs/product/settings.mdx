`/settings` brings account, workspace, credentials, and usage controls into one
page. A section rail links directly to each area.

## Provider connections

Provider connections belong to the signed-in user. The trusted backend supports
the following connections:

| Method | How it works |
| --- | --- |
| ChatGPT account | Connect Codex through the device-code flow. Settings shows the login state and lets you cancel or revoke it. |
| Model API key | Store a write-only OpenAI, Anthropic, or OpenRouter key. |
| Daytona | Store a write-only Daytona key plus an active snapshot name for optional sandbox infrastructure. |

Only metadata is visible in the UI; the reusable secret is write-only. See
[Provider connections and models](/platform/provider-connections-and-models) for
the full lifecycle and the providers served.

The page also manages organization secrets and user-owned API keys. A newly
created bearer API key is shown once; later reads return metadata only.
