title: Overview
description: Run serious work through Codex, Claude Code, OpenCode, or Pi while useAgent keeps the thread, tools, artifacts, and execution record together.
---

useAgent is a workspace for assigning work to coding agents and keeping the
result understandable. Choose an engine, connect the services it needs, attach
repositories or files, and follow the work in one durable thread. The same
thread can produce reviewable files, ask for approval, continue later, or hand a
task to a named bot.

The backend, not a browser tab or sandbox process, owns the durable record. It
stores runs and events in Postgres and streams a provider-neutral projection to
the UI. Codex, Claude Code, OpenCode, and Pi keep their own native runtime and
session grammar underneath that common product protocol.

## Start with a task

<Steps>
  <Step title="Connect what the task needs">
    Add a model-provider account or API key in Settings. Connect GitHub for
    repositories. A deployment uses one sandbox provider - Box, Cube, or
    Daytona - and may allow personal Box or Daytona connections.
  </Step>
  <Step title="Describe the outcome">
    Start a thread, choose a ready engine and model, add repositories, files,
    skills, or structured references, then send a concrete request.
  </Step>
  <Step title="Follow and review">
    The session shows messages, commands, file changes, questions, approvals,
    child activity, and artifacts as the backend records them. Reloading does
    not discard the durable history.
  </Step>
  <Step title="Continue or delegate">
    Reply in the same thread, mention a bot, schedule a routine, or use the API
    and CLI to dispatch more work.
  </Step>
</Steps>

## Read support claims correctly

Code support, deployment configuration, and live verification are different
claims. A driver can exist while a provider credential is missing; an engine
can be configured while its selected model is not ready; a sandbox adapter can
implement an operation without that engine/provider combination having current
end-to-end evidence.

Use `GET /api/capabilities` for actor-scoped engine and model availability, and
read [Verified support](/operations/verified-support) for the current evidence
boundary of this documentation snapshot.
