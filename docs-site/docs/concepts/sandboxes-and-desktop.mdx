Work runs inside an isolated sandbox, not in the backend process. The backend
drives the sandbox from outside and records everything it observes.

## Sandbox

The isolated Linux workstation where agent commands, repositories, browser
automation, desktop apps, and recordings run. A thread gets one sandbox and one
working directory, retained and reused across its runs: the lease checks
liveness and required labels before reuse and re-provisions when the retained
sandbox is stale (`backend/src/engines/thread-sandbox.ts`). A run executes
inside its thread's sandbox.

## Sandbox provider

A vendor-specific implementation selected behind a provider-neutral sandbox
contract. **Daytona**, **Cube** and **Box** implement the required process,
filesystem, preview, and lifecycle boundary and may declare optional PTY,
desktop, recording, and inventory capabilities. Box implements its native
desktop API and an interactive terminal through the Box CLI's `box ssh`; the
terminal is available only when the `box` CLI is installed on the useAgent
backend. The user supplies only the Box API key in Settings; useAgent keeps it
server-side and creates the temporary SSH setup automatically. Each provider is
a plugin package under `packages/sandbox-*`.

## Warm pool

Prepared sandboxes kept ready so a new run avoids most cold-start work. Warm-pool
claimable creation and parallelized post-sandbox preparation are part of the
turn-start latency effort.

## Desktop

When the configured provider and engine advertise desktop support, the session
can show its workstation through the authenticated desktop proxy. Provider
readiness is explicit: Box uses its native desktop endpoint, Daytona can expose
native computer use, and Cube uses trusted X11 controls. Recording is available
only when the selected provider/runtime capability is ready; a successful
recording can be published as an MP4 artifact.

## Restart reconciliation

Because the sandbox runs independently of the backend, a backend restart need not
kill a live run when that exact engine/provider session supports reconciliation:

<Steps>
  <Step title="The sandbox keeps executing">
    The retained engine process inside the sandbox is unaffected by a backend bounce.
  </Step>
  <Step title="A recovery loop re-probes">
    On restart, a background loop finds the in-flight session and streams the
    interim provider events into the timeline with a visible heartbeat.
  </Step>
  <Step title="The real result is adopted">
    The recovered run adopts the finished result, or fails honestly at a bounded
    deadline, rather than discarding work that actually completed.
  </Step>
</Steps>
