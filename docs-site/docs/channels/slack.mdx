Slack can start and continue runs through the same command lane as the web app.
It supports Events API ingress and optional Socket Mode ingress.

## Starting and continuing a run

<Steps>
  <Step title="Mention or DM to start">
    An `@mention` or a direct message starts a run after the Slack workspace and
    sender have been mapped to a product organization and user.
  </Step>
  <Step title="Reply to continue">
    Replies thread under the run, with multi-turn continuity, reusing the thread's
    history and sandbox.
  </Step>
  <Step title="Attachments ride the run">
    Inbound file attachments are attached to the run and render on the user's turn
    in the web timeline.
  </Step>
</Steps>

## Repository binding from links

GitHub links in a Slack message bind the run's repositories, validated against
the **same allowlist the web composer enforces**. The channel does not get a
weaker security posture than the web app; it shares the allowlist.

## Choosing an engine or model

Start a message with `engine:name` or `model:name` to select from the Slack
catalog. An engine can change only when a new Slack thread starts; replies keep
the thread's original engine. A model can change within the same engine.

## Results back in the thread

Answers and artifacts flow back to the Slack thread:

- A Slack-started run posts a **Block Kit run card** with title, status, model,
  repository context, and an "Open in useAgent" button.
- The card **updates in place** as the run moves from queued to running to
  completed. A plain-text fallback is available when Block Kit delivery fails.
- Approvals are resolved in the web app today; in-thread Block Kit approvals
  are deliberately deferred.

## Scoped bring-up

A per-channel ingress allowlist can restrict where Slack starts runs. Workspace
and sender mappings fail closed: an unmapped workspace is ignored, and an
unmapped sender receives linking guidance instead of starting a run.

:::tip
Everything Slack does here rides shared machinery: the command lane, the thread
stream, and the outbox. That is why Slack behaves consistently with the web app
rather than being a parallel implementation.
:::
