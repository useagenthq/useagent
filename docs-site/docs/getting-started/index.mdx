UseAgent has a Next.js frontend, a Bun backend, and a Postgres database.
Sandboxed agent work also needs a configured sandbox provider and an available
engine connection.

| Part | Local address | Responsibility |
| --- | --- | --- |
| Frontend | `http://localhost:3400` | The workspace, sessions, files, and settings |
| Backend | `http://localhost:3201` | Authentication, API, run orchestration, and event streams |
| Postgres | Configured with `DATABASE_URL` | Durable application records |
| Sandbox provider | Configured separately | Remote computers for agent work |

The browser sends `/api/*` requests through the frontend to the backend. It does
not connect to Postgres directly.

## How a task works

1. A request creates or continues a thread through the command API.
2. The backend resolves the engine, account, and execution environment.
3. The engine's output is recorded and translated into a common event format.
4. The session view reads a snapshot and receives live updates over SSE.
5. Follow-up messages continue the thread; published artifacts remain accessible
   through the app.

See [request flow](/architecture/request-flow) for the runtime details, including
direct chat, resident runtimes, and recovery.
