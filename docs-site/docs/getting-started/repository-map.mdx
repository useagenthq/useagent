## Apps and supporting directories

| Path | Responsibility |
| --- | --- |
| `frontend/` | Next.js workspace, session timeline, artifacts, knowledge, and settings |
| `backend/` | Bun and Hono API, database, orchestration, adapters, and gateway |
| `docs-site/` | This Blume documentation site |
| `docs/architecture/` | Detailed architecture notes and the request-flow diagram |
| `infra/self-host/` | Host bring-up script and Hetzner reference provisioning |
| `memory/` | Optional shared memory service setup and operating notes |

## Shared packages

| Package | Responsibility |
| --- | --- |
| `agent-client` | Typed HTTP helpers, event streams, reducers, selectors, and fleet client |
| `agent-harness` | Canonical engine events and adapter contracts |
| `sandbox-contract` | Common sandbox interface and provider capability model |
| `artifact-workspace` | Workpiece types, actions, and export capability definitions |
| `artifact-formats` | Native document, spreadsheet, presentation, and PDF handling |
| `conformance` | Deterministic client and harness contract tests |
| `cli` | Terminal commands and a stdio MCP server for dispatching fleet work |

Each package has its own `package.json`. The root typecheck lists its checks
explicitly; adding a package does not automatically add a root check.

## Follow a task through the source

1. **Page and composer:** `frontend/app/page.tsx`,
   `frontend/app/session/new/page.tsx`, and `frontend/components/chat/`.
2. **HTTP routing and boot:** `backend/src/index.ts`.
3. **Commands, runs, and recovery:** `backend/src/runs/` and
   `backend/src/worker.ts`.
4. **Engine adapters:** `backend/src/engines/`.
5. **Shared event contract:** `packages/agent-harness/src/` and
   `packages/agent-client/src/`.
6. **Session rendering:** `frontend/app/session/(thread)/[id]/page.tsx` and
   the chat timeline components.

## Useful entry points

- `frontend/app/lab/session/page.tsx` hosts a synthetic session for inspecting
  the real timeline components.
- `backend/src/knowledge/gateway/` implements trusted tools and approvals.
- `backend/src/provider-connections/` handles provider accounts and credentials.
- `backend/src/artifacts/` owns artifact storage, routes, and publishing.
- `backend/drizzle/` contains committed database migrations.
- `packages/cli/src/bin.ts` is the CLI entry point.

Read [shared packages](/architecture/shared-packages) for the dependency
boundaries and [request flow](/architecture/request-flow) for the end-to-end path.
