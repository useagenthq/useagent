This page is everything a facilitator needs to run a one-hour hands-on session.
Attendees leave with an account, a finished mini-project, and a working mental
model of agent-assisted coding.

**Audience:** students who can edit code and use a terminal, no AI experience
needed. **Group size:** 5–30. **Requirements:** one laptop per attendee, Wi-Fi,
and a projector for the facilitator.

## Before the session (facilitator, 15 minutes of prep)

1. Create your own account at [app.useagent.org](https://app.useagent.org) and
   run one session end to end so the UI is familiar.
2. Open the [slide deck](/getting-started/students-workshop-slides) and skim it
   once; it mirrors the timeline below.
3. Have a fallback ready: if Wi-Fi struggles, attendees pair up and share one
   laptop.

## Timeline

### 0:00–0:05 — What is an agent workspace? (slides 1–3)

Show the concept: you describe work in plain language, an agent does it in an
isolated workspace, you watch live and keep the output. One sentence to land:
"you are the reviewer now, not the typist."

**Expected output:** none — just attention.

### 0:05–0:15 — Live demo (slides 4–5)

In front of the room, start a session and give the agent a tiny task, for
example: "Create an HTML page that shows our club's name with a button that
changes its color." Narrate what you see: the plan, the files appearing, the
result.

**Expected output:** attendees have seen one full task complete.

### 0:15–0:20 — Everyone signs up (slide 6)

Attendees create accounts at [app.useagent.org](https://app.useagent.org). Walk
the room; this is the moment where people get stuck on sign-in details.

**Checkpoint:** every attendee has the app open and can start a session.

### 0:20–0:45 — Hands-on: the portfolio sprint (slides 7–9)

Everyone runs starter project #1 from the
[student guide](/getting-started/students): a personal portfolio page.

- **0:20–0:30** — first prompt from the guide, verbatim is fine. Attendees watch
  their agent work.
- **0:30–0:40** — one follow-up change of their own choosing (colors, layout,
  content). Encourage them to be picky; reviewing is the skill.
- **0:40–0:45** — two volunteers show their pages and say what they asked for.

**Checkpoint:** every attendee has a page their agent built and at least one
revision they requested.

### 0:45–0:55 — What just happened? (slides 10–11)

Short discussion. Good prompts for the room:

- What did the agent do well? Where did it guess wrong?
- What would you *not* trust it with yet?
- How is this different from copying code from a chatbot?

Key idea to land: the agent's output is only as good as your spec and your
review.

### 0:55–1:00 — Where to go next (slide 12)

Point attendees at the two remaining starter projects in the
[student guide](/getting-started/students) as homework, and at the
[Quickstart](/getting-started/quickstart) if anyone wants to self-host.

## After the session

- Ask attendees to finish one more starter project during the week.
- Share a short report (attendance, what worked, what confused people) on
  [issue #51](https://github.com/useagenthq/useagent/issues/51) — it directly
  improves this kit.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Sign-up email not arriving | Check spam; use a personal email if the university filter eats it |
| Agent seems stuck | Refresh the session view; the timeline is live but browsers sleep |
| Room Wi-Fi saturated | Pair up; the demo plus one shared hands-on still lands the lesson |
| Someone finishes early | Point them at starter project #2 (notebook to report) |
