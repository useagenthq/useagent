## One backend per database

Run one backend against a given database. Provider-event draining and the
realtime event fan-out include process-local state.

`REQUIRE_SINGLE_BACKEND=true` makes the boot-time Postgres advisory lock
mandatory: contention or an unavailable guard fails startup. The parser also
accepts `1`. When the flag is absent, false, or zero, the guard warns and can
continue; production mode does not automatically enable it.

An outbox row lock protects a worker's claim. It does not make all event
publication and recovery safe across multiple backend replicas.

## Preserve the startup order

The current backend starts its durable state in this order:

1. Enforce the single-backend guard.
2. Apply committed Drizzle migrations.
3. Reconcile the restricted gateway role's grants.
4. Seed development identity records.
5. Reconcile fleet leases and admissions.
6. Recover stale runs.
7. Reset stuck canonicalization and learning work for retry.

Changing this order can let recovery use an outdated schema or count an old
sandbox lease against new work. Add gateway table permissions with the
migration that makes those tables necessary.

## Keep credential boundaries explicit

Provider connection APIs expose status and metadata, not reusable credential
values. The provider gateway resolves credentials for supported model calls.

That is separate from user-configured task secrets and subscription auth.
Production task-secret policy uses `gateway_only`; development compatibility
can support sandbox injection. Some engine authentication flows also place
scoped or synchronized auth material in a runtime. Do not describe every
credential as permanently absent from sandboxes.

See [secrets](/product/secrets) and
[provider connections](/platform/provider-connections-and-models).

## Give the gateway a restricted role

The dedicated gateway uses `GATEWAY_DATABASE_URL` and a restricted database
role. The backend reconciles its grants from `backend/src/db/gateway-grants.ts`.

The gateway checks that signing and encryption secrets are independent of
each other and of the auth secret. Configure the deployment to preserve this
separation instead of reusing one value for every service.

## Preserve files as well as database records

Artifact metadata is stored separately from artifact bytes. The local storage
adapter uses `ARTIFACT_STORAGE_DIR`, defaulting to `backend/.artifacts`.
A database restore without those files can leave visible artifact records
whose downloads fail.

Keep required environment and encryption material available for recovery.
See [backups and restore](/operations/backups).
