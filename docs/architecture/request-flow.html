useAgent architecture · live control plane

One request, from intent to durable result.

The browser submits a durable command. The control plane prepares scoped context, dispatches an isolated resident agent, brokers every privileged capability through signed gateways, and streams persisted events back to one realtime thread.

01 · Durable request path Browser edge to trusted control plane
Ingress

Web, Slack, schedule, API

One authenticated command shape, regardless of where the request starts.

  • Org and user identity
  • Prompt, files, repos, model
Admission

Auth + command boundary

Checks tenant, model policy, readiness, and idempotency before accepting work.

  • Thread advisory lock
  • Command + run in one transaction
Source of truth

Postgres event core

Queued run, steps, native frames, canonical events, audit, and outboxes.

  • Persist before publish
  • Replay after reconnect
Context

Parallel run preparation

Loads only the context required for this turn, concurrently.

  • Memory + thread preamble
  • Skill catalog + pinned skill
  • User uploads
Isolation

Cube or Daytona sandbox

Warm thread workspace with resident Codex, OpenCode, or Claude runtime.

  • Repos and terminal
  • Desktop + recording
  • No long-lived provider keys
Agent loop

Native engine harness

The selected agent reasons, edits, runs tools, delegates, and emits native events.

  • Resume by native session ID
  • Approvals and cancellation
02 · Signed capability plane Sandbox is isolated; gateways hold authority
Model traffic

Provider gateway

Validates the live run capability, resolves the org credential server-side, applies limits and retry policy, then audits the upstream request.

MCP traffic

Knowledge + tool gateway

Lists only tools allowed for the live run, then executes with tenant, user, thread, and run identity taken from the signed token.

External systems

Models, web, apps, repos

OpenAI, Anthropic, OpenRouter, memory, browser, GitHub, Slack, Loop login, artifact publishing, automations, and child sessions.

03 · Realtime return path Durable replay plus low-latency live deltas
Product surface

Unified session UI

Chat, tool details, agents, editor, terminal, desktop, artifacts, and approvals share one thread state.

Client state

Canonical thread store

Upserts stable event IDs, collapses replay/live overlap, and renders without a refresh.

Transport

One thread SSE

Snapshots, run lifecycle, steps, deltas, native frames, canonical events, and completion.

Normalization

Canonical event lane

Preserves provider-native detail while projecting shared tool, subagent, approval, artifact, and message semantics.

Write order

Persist, then publish

Steps and provider frames land in Postgres before they become visible to connected clients.

Engine output

Text, tools, files, status

Native engine events and transient token deltas leave the sandbox through the adapter.

04 · Trust boundaries and failure behavior Least authority, bounded recovery
Browser edge

Session auth and org membership are resolved server-side. Browser IDs never establish tenant authority.

Sandbox boundary

Ephemeral signed capabilities replace database, memory, and provider credentials inside the runtime.

Gateway boundary

Every privileged call is bound to a currently active run and is logged with bounded request metadata.

Recovery boundary

Idempotent commands, durable events, native session IDs, and SSE replay make reconnect and resume safe.
